# Codex 自动化设置

这个 skill 很适合配合 Codex 自动化使用：你把文件放进 `TBD`，自动化定时检查，有文件就处理一批，没有文件就结束。

## 推荐自动化提示词

可以把下面这段作为自动化任务说明：

```text
使用 doc-to-word-converter skill 处理当前工作区的 TBD 文件夹。
先初始化并检查 TBD、Done、New 文件夹，然后运行状态统计和复杂度评估。
质量第一：根据当前上下文长度和文件复杂度选择合适处理密度，复杂或不确定文件单独处理。
转出的 Word 横版或竖版必须根据原文档结构检测决定，不能默认横版。
图片型表格、评价表、费用标准表要优先保留原表结构：明细行独立，源表有意义的分组合并要保留，斜线表头和多级表头不能随意扁平化。
每完成一个文件后运行隐私检查、质量检查和必要的表格粒度检查；通过后把原文件移动到 Done，把生成的 Word 放到 New。
报告已处理多少、已生成多少、TBD 还剩多少。
如果上下文太长或还有复杂文件需要继续，明确提醒我新建对话继续。
```

## 自动化适合处理什么

适合：

- 固定格式表单；
- 有文本层的 PDF；
- 结构比较清楚的制度文件；
- 每次新增少量待转换文件的工作流；
- 需要反复跑隐私检查和质量检查的场景。

不适合一次性硬跑：

- 大量扫描件；
- 多页复杂图片表格；
- 需要人工判断很多细节的合同；
- 表格边框不清楚、截图分辨率很低的文件。

这些文件最好单独处理。自动化可以先把它们标记出来，不要为了“批量完成”牺牲质量。

## 什么时候应该中断

如果出现下面情况，建议不要继续往下跑：

- OCR 文字很长，当前对话已经很拥挤；
- 表格结构不确定；
- 隐私检查反复失败；
- Word 打开后需要人工确认；
- 你已经开始觉得“差不多就行”。

这个 skill 的原则是：慢一点没关系，别把不好用的 Word 当成完成。

## 状态统计

自动化每轮结束前建议运行：

```bash
python scripts/status_report.py "/你的/转换工作区" --json
```

你应该关注三个数字：

| 字段 | 含义 |
|---|---|
| `processed_count` | 已放进 `Done` 的源文件数量 |
| `new_count` | 已生成的 Word 数量 |
| `remaining_count` | `TBD` 里还剩多少文件 |

只要 `remaining_count` 不为 0，就说明还有文件没处理完。
