# Codex 自动化设置

这个 skill 适合做成一个简单的“待转换文件夹监控”：定时看一眼 `TBD`。有文件就评估、转换、检查；没有文件就报告为空。

顶层的 [AUTOMATION_PROMPT.md](../AUTOMATION_PROMPT.md) 已经放了一份可直接复制的提示词。下面是设置思路和注意事项。

## 自动化要做什么

自动化不应该一上来就转换。它应该先做三件事：

1. 确认当前工作区存在 `TBD / Done / New`；
2. 运行状态统计，看看 `TBD` 里有没有文件；
3. 只有 `TBD` 不为空时，才进入复杂度评估和转换流程。

这样设置后，你只需要把待转换文件或邮件附件导出的文件放进 `TBD`。自动化运行时会自己判断本轮要不要处理。

## 推荐提示词

```text
使用 doc-to-word-converter skill 检查当前工作区的 TBD 文件夹。
先初始化并确认 TBD、Done、New 三个文件夹存在，然后运行状态统计。
如果 TBD 为空，只报告“本轮没有待转换文件”，不要做其他操作。
如果 TBD 里有需要转换的文件或邮件附件导出的文件，先运行复杂度评估，再按质量优先原则选择本轮处理范围。
复杂、不确定、图片型、扫描型、表格结构复杂的文件，一律单独处理。
转出的 Word 横版或竖版必须根据原文档结构检测决定，不能默认横版或默认竖版。
表格还原要遵守：明细行保持独立；源表中有意义的分组合并要保留；斜线表头、多级表头、分组表头不能随意扁平化；不能把整页截图当成最终 Word。
每完成一个文件，都要运行隐私清理、隐私检查、质量检查；表格型文件还要运行表格粒度检查。
检查通过后，原文件移动到 Done，生成的 Word 放到 New。
最后报告：本轮处理了多少个文件、生成了多少个 Word、TBD 还剩多少个文件。
如果上下文变长、检查失败或文件结构不确定，停止继续批处理，并说明需要人工确认或新建对话继续。
```

## 建议频率

日常使用时，可以每天或每半天跑一次。  
如果你正在集中整理一批旧文件，更建议手动触发。先看上一轮 Word 是否能用，再继续下一批。

## 适合自动化处理的文件

- 固定格式表单；
- 有文本层的 PDF；
- 结构清楚的流程文件；
- 页数不多的业务表格；
- 每次新增少量待转换文件的工作流。

## 不建议直接批量自动化的文件

- 大量扫描件；
- 多页复杂图片表格；
- 分辨率很低的截图；
- 表格线不清楚的图片；
- 需要人工判断敏感信息边界的合同或协议；
- OCR 结果明显不稳定的文件。

这些文件可以让自动化先识别出来，但不要硬转。留在 `TBD`，单独开一轮处理会更稳。

## 状态统计

每轮结束前建议运行：

```bash
python scripts/status_report.py "<workspace>" --json
```

重点看三个数字：

| 字段 | 含义 |
|---|---|
| `processed_count` | 已放进 `Done` 的源文件数量 |
| `new_count` | 已生成的 Word 数量 |
| `remaining_count` | `TBD` 里还剩多少文件 |

如果 `remaining_count` 大于 0，说明还有文件没处理完。此时不要默认继续硬跑，要结合文件复杂度和当前上下文判断。

## 失败时怎么处理

自动化遇到下面情况，应该停下来报告，而不是继续批量跑：

- 隐私检查失败；
- 表格粒度检查失败；
- 方向检测失败；
- 依赖缺失，例如缺少 `python-docx` 或 OCR 工具；
- 输出 Word 需要人工打开确认；
- 当前对话已经有大量 OCR 文本或长日志。

这类文件不是不能处理，而是应该单独处理。
