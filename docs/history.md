# 优化记录

这个 skill 的规则不是一次写完的，而是在真实文件转换里慢慢补出来的。

## 1. 先解决版式方向

最早的问题是横版、竖版容易被默认处理。很多工具会把所有文件都按竖版输出，或者在做表格时一律套横版。

现在的规则是先检测：

- PDF 看页面宽高；
- DOCX 看 section 方向；
- PPT/PPTX 看 slide 宽高；
- 图片看像素宽高。

检测到横版就输出横版，检测到竖版就输出竖版。检测失败时才保守用竖版，并在报告里说明。

## 2. 再解决“看起来像表格，其实不好编辑”

有些图片型 Word 或截图表单，人工看很清楚，但自动重建时很容易偷懒：把一整块内容塞进一个单元格。

这会导致 Word 打开后没法逐项编辑。于是新增了表格粒度规则：

- 评价项、检查项、评分项，一项一行；
- 单元格里不能塞太多换行；
- 大表格不能被压缩成几行。

## 3. 后来发现不能把合并都拆掉

另一次转换里，评价表原本有清楚的分组合并。第一次修正时把所有单元格都拆开了，结果又不像原表。

这说明规则不能走极端。现在的判断是：

- 明细行必须独立；
- 分组标签可以合并；
- 源表里的类别块、评分标准块、评估结果块、备注块，要按原结构保留；
- 不为了省事合并，也不为了“独立”强拆。

## 4. 复杂表头单独补规则

制度文件里的费用标准表经常有复杂表头：

- 左上角斜线表头；
- 两级表头；
- 横向分组表头；
- 合并列。

这些结构如果被扁平化，文字还在，但业务人员一眼就会觉得不对。现在 skill 明确要求复杂表头按源表重建，能用 Word 斜线边框就用斜线边框。

## 5. 为什么坚持每个文件后都检查

文档转换很容易“第一眼能看，第二眼难改”。所以这个项目把检查放进标准流程：

- 隐私清理；
- 隐私检查；
- 基础质量检查；
- 表格粒度检查；
- 必要时人工打开复查。

只有通过检查后，源文件才移动到 `Done`，输出 Word 才放进 `New`。

这套流程慢一点，但更接近真实工作里能交付的结果。
